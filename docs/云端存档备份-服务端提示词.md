# 云端存档备份：给服务端 AI 的提示词

> 用途：WFMC 启动器（`H:\mcqidongqi`）现在只能**本地**备份存档；要加「存档备份也上云」。
> 客户端这边（我）负责上传/下载/列表/UI，**服务端那半边**由笔记本服务器上的 AI 做。
> 下面的「提示词」整段复制给它即可，后面两节是我自己的实现约定，不用复制。

## 一、复制给服务端 AI 的提示词

```text
你是 WFMC 统一账号服务端（H:\笔记本服务器，线上在笔记本 WSL 的 /srv/api/）的维护者。
现在客户端 WFMC 启动器要新增「云端存档备份」功能，需要服务端补一组新接口。请按下面的契约实现。

【背景（先读这些文件，别猜）】
- H:\笔记本服务器\docs\交接文档.md（服务端结构、发布流程）
- H:\mcqidongqi\docs\服务端交接.md（客户端视角的现有接口清单、错误约定、配额）
- 现有代码：app.py（路由）、store.py（PostgreSQL）、security.py（令牌校验）
现有的 /v1/backup 是**配置包快照**（KV 快照，单条 ≤2MB、单账号 50MB），
绝对不能拿来存存档 zip（存档动辄几十上百 MB，复用会直接撑爆配额）。要新开一组「文件对象」接口。

【必须遵守】
1. 纯新增，不改任何现有接口语义；老客户端不受影响。
2. product 隔离照旧：只能看到自己 token 对应 product + user 的数据，跨账号一律 404。
3. 大文件必须**流式落盘**（chunked read → 临时文件 → 完成后原子 rename + 算 sha256），
   不许把整个 body 读进内存 —— 备机棒子只有 373MB 内存。
4. 错误格式沿用现有约定 { "error": { "code": "...", "message": "中文人话" } }，
   message 直接给用户看，不要返回英文或堆栈。
5. 保留份数、单文件上限、单账号总量都放进 store 的可配置项（和 backup_keep() 一样可后台改），
   通过 limits 字段回给客户端，客户端不硬编码。

【接口契约】
所有接口都要 Bearer token（复用现有鉴权），product 从 token 取。

1) 上传
   POST /v1/saves/upload
   Query: instance=<实例ID，客户端生成，稳定不变>
          name=<zip 文件名，URL 编码>
   Header: Content-Type: application/zip
           X-WFMC-Meta: base64(JSON)，字段：
             { instance, instance_name, mc_version, loader, loader_version,
               worlds: ["世界A","世界B"], files: 1234, created_at: 毫秒时间戳, sha256 }
   Body: zip 原始字节（可能 1MB～500MB）
   200 → { "id": "sv_xxx", "instance": "...", "bytes": 123, "sha256": "...",
           "created_at": 1700000000, "deduped": false }
   幂等：同一 user+product+instance 下 sha256 已存在 → 直接返回那条记录，deduped=true，不新增、不重复计费。
   错误：file_too_large / quota_exceeded / bad_request（meta 缺失或 JSON 坏了）

2) 列表
   GET /v1/saves?instance=<可选，给了就只回这个实例>
   200 →
   { "items": [ { "id","instance","instance_name","mc_version","loader","loader_version",
                  "worlds":[],"files":123,"bytes":123,"sha256":"...",
                  "created_at":1700000000 } ],
     "limits": { "saves_keep": 10, "max_file_mb": 500, "quota_bytes": 2147483648,
                 "used_bytes": 123456 } }
   按 created_at 倒序。limits 里 used_bytes 用于客户端显示「云盘用掉多少」。

3) 下载
   GET /v1/saves/{id}/download
   200 → 原始 zip 字节，Content-Type: application/zip，Header 带 X-Sha256。
   客户端会自己校验 sha256 再落盘。

4) 删除
   DELETE /v1/saves/{id} → 200 { "ok": true }（幂等，不存在也 200）

5) 用量（给客户端显示，可选但建议）
   GET /v1/saves/usage → { "used_bytes": 1, "quota_bytes": 2, "count": 3, "instances": 4 }

【保留策略】
- 每个 (user, product, instance) 保留最近 N 份，N 默认 10，可配；写入新的一份后立刻按 created_at 删掉超出的，
  并返回实际保留数（如果方便，放在 items 之外不影响兼容）。
- 单文件上限默认 500MB，单账号总量默认 2GB（都是可配置常量）。

【存储】
建议 /srv/api/data/saves/<product>/<user_id>/<instance>/<id>.zip，
PostgreSQL 里只存索引表 saves(id, product, user_id, instance, instance_name, mc_version, loader,
loader_version, worlds jsonb, files, bytes, sha256, created_at)，别把 blob 塞进数据库。
注意备机磁盘只有 6.7G，写之前先检查剩余空间，不够就返回 quota_exceeded。

【验收（请自己 curl 跑一遍，把输出贴给我）】
1. 上传一个 100MB 的假 zip → 200 且返回 id/sha256
2. GET /v1/saves → 能看到 instance / instance_name / mc_version 三个字段
3. 下载回来 sha256 与上传时一致
4. 同一文件再传一次 → deduped=true，列表条数不增加
5. 传第 11 份 → 最旧那份被删，剩下 10 份
6. 不带 token → 401；用 A 账号的 token 下载 B 账号的 id → 404
7. 传超过上限的文件 → file_too_large + 中文提示

【交付】
- 改完更新 H:\笔记本服务器\docs\交接文档.md 的接口表（新增这一节）
- 需要让客户端（我）知道的任何偏差，写成「与契约不一致的地方」清单
- 不要动 /v1/backup、/v1/sync 的任何行为
```

## 二、客户端这边我会怎么接（给服务端 AI 的补充说明，不用它实现）

- 本地备份照旧永远先做（离线可用），云端是「多一份保险」。
- 上传时机：本地 `createBackup()` 成功、且已登录、且云端开关开着 → 后台异步上传，失败不打扰用户，只记一条状态。
- 上传成功后把云端 `id` 写回本地那份备份的 `.zip.json` 元数据，界面上点亮「已同步云端」。
- 存档页新增「云端备份」区：按 **实例 → MC 版本 → 整合包 → 日期** 分组展示（这四项都由 X-WFMC-Meta 带上去，所以服务端必须原样存、原样回）。
- 「从云端还原」= 下载 zip → 复用现有 `restoreBackup()`（已有 zip-slip 防护），回滚前仍然先本地备份一次。
