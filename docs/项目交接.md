## 0. 一句话

WFMC（WanFan Minecraft Launcher）是 Electron + React + TypeScript 的 Windows Minecraft 启动器，产物是**两个 exe**：便携版（单文件双击即用）和 NSIS 安装版（可选安装位置、可自动更新）。自动更新走 **GitHub Release**（仓库 `steveliuyan/wfmc`），和服务端完全解耦 —— 服务端挂了不影响更新，反之亦然。

| 项 | 内容 |
| --- | --- |
| 目录 | `H:\mcqidongqi` |
| 应用标识 | `appId` = `com.wanfan.wfmc`，`productName` = `WFMC` |
| 技术栈 | Electron 38 · React 19 · TypeScript 5.9 · Vite 7 · esbuild · electron-builder 26 |
| MC 内核 | `@xmcl/core` / `installer` / `user` / `modrinth` / `curseforge` |
| 本机环境 | Node v24.17.0、npm 11.13.0、Windows（**没有 git / gh CLI**，全部走 Node 脚本 + REST API） |
| 规模 | `src/main/` 59 个 ts、`src/renderer/` 36 个 ts/tsx |
| 产物 | `release\WFMC-Setup-<ver>.exe`、`release\WFMC-Portable-<ver>.exe`（各 ~93–98MB） |

## 1. 跑起来

```powershell
cd H:\mcqidongqi
npm install            # 首次；electron 下载失败见 HANDOFF §13.1（镜像已在 .npmrc 配好）
npm run dev            # 开发（Vite + Electron 热更新）
npm start              # 跑编译产物
npm run typecheck      # tsc --noEmit，提交前必跑
npm run smoke          # 联网冒烟：解析版本 / JVM 参数 / Fabric / Modrinth / Java 探测
```

`npm run build` = `build:main`（esbuild 打 `src/main/*.ts` → `dist/main`）+ `build:renderer`（vite → `dist/renderer`）。

## 2. 打包（发版第一步）

```powershell
cd H:\mcqidongqi
npm run dist              # = build + electron-builder --win --x64（portable + nsis 都打）
npm run dist:portable     # 只打便携版
npm run dist:setup        # 只打安装版
```

镜像已写在 `.npmrc`（`electron_mirror` / `electron_builder_binaries_mirror`），不用手设环境变量；手敲 `npx electron-builder` 时才需要：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

**打包前先关掉正在运行的 WFMC/electron 进程**（占用 `release\win-unpacked\WFMC.exe` 会让 electron-builder 报 EBUSY）：

```powershell
Get-Process electron,WFMC -ErrorAction SilentlyContinue | Stop-Process -Force
```

打完检查 `release\`：只能有**当前版本的两个 exe** + `win-unpacked\`（留着测打包版）。旧 exe 留着会被发布脚本一起传上去 —— 见第 4 节。

> **坑（2026-11-07 真踩）**：用 PowerShell `Set-Content -Encoding utf8` 改 `package.json` 会写进 BOM，vite 读它做 PostCSS 配置时直接崩：
> `[vite:css] Failed to load PostCSS config … Unexpected token '﻿', "﻿{"name"… is not valid JSON`。
> 改 `package.json` 请用无 BOM 写法：
> ```powershell
> $t=[IO.File]::ReadAllText("H:\mcqidongqi\package.json").TrimStart([char]0xFEFF)
> [IO.File]::WriteAllText("H:\mcqidongqi\package.json",$t,(New-Object Text.UTF8Encoding($false)))
> ```

## 3. 发布到 GitHub

仓库 `steveliuyan/wfmc`（public）。本机没有 git/gh，发布 = **Node 脚本 + GitHub REST API**。

### 3.1 token 与代理

token 只在 `H:\mcqidongqi\.local\gh-token.txt`（classic，仅 `repo` 权限，login = steveliuyan）。`.local/` 已在 `.gitignore` 且 `opensource.mjs` 的 `SKIP_DIRS` 会跳过，**永远不会被推上去**。真 token 绝不许出现在会被推送的文件里（GitHub push protection 会 422 挡掉整次推送）。

```powershell
cd H:\mcqidongqi
foreach($n in 'HTTP_PROXY','HTTPS_PROXY','http_proxy','https_proxy','ALL_PROXY','all_proxy','NODE_USE_ENV_PROXY','NO_PROXY','no_proxy'){ Remove-Item -Path ("env:"+$n) -ErrorAction SilentlyContinue }
$env:GH_TOKEN = (Get-Content .local\gh-token.txt -Raw).Trim()
```

token 失效：https://github.com/settings/tokens/new?scopes=repo 重新生成，覆盖写回同一个文件。

### 3.2 发 Release（上传 ~185MB，要 10 分钟以上，放后台）

```powershell
Start-Process -NoNewWindow node -ArgumentList "scripts\publish-github.mjs","--owner","steveliuyan","--repo","wfmc","--tag","v1.1.2","--notes","CHANGELOG.md" -RedirectStandardOutput .pub-out.log -RedirectStandardError .pub-err.log
Get-Content .pub-out.log -Encoding UTF8 -Tail 6     # 看到两个 exe 都「上传完成」才算完
```

脚本会：校验 token → 建/复用仓库 → 用 `CHANGELOG.md` 顶部那一段当更新说明建 release → 把 `release\*.exe` 逐个传上去 → 打印「更新源该填什么」。
（根目录还有个 `发布到GitHub.bat`，是给手动粘贴 token 的场景用的，等效。）

### 3.3 推源码（可选，和发版分开）

```powershell
node scripts\opensource.mjs --repo wfmc --message "feat: WFMC 1.1.2 弹窗通知"
```

只推源码：`node_modules` / `dist` / `release` / `WFMC-Data` / 日志 / `HANDOFF.md` / `.local` 全部不进（规则同 `.gitignore` + SKIP 名单）。**别把 exe 传进仓库**。

### 3.4 复核

```powershell
node -e "const r=await fetch('https://api.github.com/repos/steveliuyan/wfmc/releases',{headers:{Authorization:'Bearer '+process.env.GH_TOKEN,'User-Agent':'x'}});const j=await r.json();for(const x of j)console.log(x.tag_name,(x.assets||[]).map(a=>a.name).join(' + '))"
```

期望：**只有一个 release**，两个 exe 都在、量级对。

## 4. 删除旧版本（三处，发完必做）

理由：客户端更新源是「这个仓库的所有 release，取最新的」，线上留一堆旧 release 容易串版本、也白占空间。

### 4.1 GitHub 上的旧 release（脚本，推荐）

```powershell
node scripts\cleanup-releases.mjs --owner steveliuyan --repo wfmc --keep v1.3.1 --dry   # 先看会删什么
node scripts\cleanup-releases.mjs --owner steveliuyan --repo wfmc --keep v1.3.1         # 真删
```

它把 `--keep` 之外的所有 release **连 git tag 一起删掉**。删之前确认新的那个 release 两个附件都在，否则会删出空档。

### 4.2 本机 `release\` 里的旧 exe

```powershell
cd H:\mcqidongqi
Get-ChildItem release -Filter *.exe | Where-Object { $_.Name -notmatch '1\.3\.1' } | Remove-Item -Force
Remove-Item release\builder-debug.yml -ErrorAction SilentlyContinue
```

### 4.3 `release\_old\`（历史留档，可整目录删）

放的是最早的 1.0.46/1.0.48 之类老包，只在想留个纪念时保留；不留就直接删掉整个 `_old`。
`release\WFMC-Data\` 是测试打包版时产生的运行数据，`win-unpacked\` 是主程序解包目录（测打包版用），都可以随时删、打下一个包时重新生成。

## 5. 自动更新怎么工作（别乱改）

- `src/main/updater.ts` 只认 **GitHub Releases**：把更新源（`settings.updateUrl`，默认烘死 `steveliuyan/wfmc`）转成 `https://api.github.com/repos/<owner>/<repo>/releases?per_page=30`，多版本模式，能列历史版本 + 更新说明 + 附件。
- GitHub API 在国内常连不上，代码按 **直连 → gh-proxy.com → ghfast.top** 顺序兜底（同样是下载 exe 时的镜像链）。
- **安装版**更新 = 下载 Setup 后跑它（不是覆盖 exe）；**便携版**更新 = 下 Portable 替换并重启。
- 所以：**发版就是发 Release**，不涉及任何服务器；也不用 `latest.yml`（这不是 electron-updater 那套）。

## 6. 版本号与 CHANGELOG 规矩

1. `package.json` 的 `version` 改掉（改法见第 2 节的 BOM 坑；`src/main/updater.ts:15` 有一处注释里写着 `1.1.0` 是示例，别被批量替换误伤）。
2. `CHANGELOG.md` **顶部**加一节 `## x.y.z（YYYY-MM-DD）`（现在的实际写法，见 1.3.1 那节）：一句话概述 → `### 分组小标题` 逐条。
   另写一份 `docs\更新说明-<ver>.md`，只放这一版的内容，**发版时用 `--notes` 指它**；不指的话 `publish-github.mjs` 默认拿整个 `CHANGELOG.md` 当 Release 说明，历史会一起贴上去。
3. 打包 → 发布 → 删旧版本（第 2–4 节）。

## 8. 踩坑清单（摘要，全文见 `HANDOFF.md` §13）

1. **NSIS 更新分支会删整个安装目录** —— `build\installer.nsh` 里的 `customRemoveFiles` 就是拦这个的，**别删**；数据目录绝不许落在安装目录里（否则更新一次数据全丢）。
2. **安装版更新是「跑下载到的安装包」**，不是覆盖 exe。
3. **改过 `installer.nsh` 或向导位图必须重打 Setup 并亲眼看一遍安装向导**（`win-unpacked` 看不出安装包装了什么）。
4. **便携版没有开始菜单快捷方式** → Windows 可能吞掉右下角系统通知（我们已补 `app.setAppUserModelId` 但还是看运气）；应用内模态框一定会弹。
5. `package.json` 写 BOM 会让 vite 直接失败（见第 2 节）。
6. 打包前没关 electron → `win-unpacked` 被占用报 EBUSY。
7. 通知是**拉取式**：启动 ~6 秒拉第一次，之后每 60 秒一次；未登录只看得到 `audience=public` 的通知。后台发「弹窗」通知记得选对模式，否则只亮红点。

## 9. 和服务端的关系

客户端登录、云备份、云同步、通知都走统一账号服务 `https://api.20050905.xyz`（`UNIFIED_PRODUCT='wfmc'` 硬编码在 `src/main/unifiedapi.ts:24,27`）。接口清单、错误码、数据表、双机切换、服务端发布流程都在 **`docs/服务端交接.md`**。

改东西的顺序：**只改客户端不动协议 → 随便发版**；**要改接口 → 先改两份文档 → 服务端上线（向后兼容）→ 客户端跟进**。

## 10. 自检工具（不想开界面手点时用）

- `npm run typecheck` / `npm run smoke`：每次发版前跑。
- 环境变量截图钩子（`src/main/index.ts` 内置，跑 `release\win-unpacked\WFMC.exe` 也生效）：
  - `WFMC_SHOT=<png 路径>`：`did-finish-load` 后等 `WFMC_SHOT_DELAY` 毫秒（默认 2500）截图并退出；
  - `WFMC_SHOT_JS=<js>`：截图前执行（点按钮、清 localStorage）；
  - `WFMC_SHOT_DOM=<json 路径>` + `WFMC_SHOT_SEL=<css>`：导出节点矩形/类名；
  - `WFMC_SHOT_PAGE` / `WFMC_SHOT_MUSIC`：指定页面。
- 例：验证通知弹窗 —— `WFMC_SHOT_JS` 里点 `.notice-popup .btn.primary`，再用 `WFMC_SHOT_DOM` 看 `.dialog-mask` 是否变空。
