# WFMC 服务端交接（客户端视角：服务端到底做了什么）

> 写给接手 WFMC 的人 / AI。目的：让你不用翻服务端代码，也能知道 WFMC 依赖的服务器有哪些、各自负责什么、接口怎么调、坏了怎么查。
>
> - 对应版本：WFMC **1.1.1** ↔ 服务端 **v1.0.0**（2026-11-07 实测）
> - 服务端代码：`H:\笔记本服务器`（线上在笔记本 WSL 的 `/srv/api/`）
> - 本文件与 `docs/SERVER-API.md` 的关系：`SERVER-API.md` 是**动手前的接口契约草稿**（当时猜的 `/api/v1` 路径），实际实现以**本文件**为准。

## 0. 一句话

WFMC 的云能力（登录、云备份、云同步、公告）**全部来自一台自建服务器** `https://api.20050905.xyz`。客户端里这个地址是硬编码常量，界面上不出现、也不允许用户改。

```ts
// src/main/unifiedapi.ts
export const UNIFIED_BASE_URL = 'https://api.20050905.xyz'
export const UNIFIED_PRODUCT = 'wfmc'
```

服务端是**单文件 Python（标准库 `http.server`）+ PostgreSQL**，不依赖任何 Web 框架。整个后端就一个 `app.py`（约 3300 行）+ 十几个模块（`store.py` 数据库、`mailer.py` 发信、`security.py` 加密、`siteswitch.py` 主备切换…）。

## 1. 三个服务，别搞混

| 名称 | 地址 | 代码 | WFMC 用它吗 |
|---|---|---|---|
| **统一账号服务** | `https://api.20050905.xyz`（内网 `127.0.0.1:8000`） | `/srv/api/app.py` | ✅ **只用这一个** |
| 老 WFMC 云同步服务 | 内网 `127.0.0.1:8010`，数据在 `/srv/wfmc/data` | 独立进程 `wfmc-api` | ❌ 1.1.x 不再直连（管理后台透过 `/v1/admin/wfmc/*` 转发，仅用于查看旧备份/旧账号） |
| 管理后台 | `https://api.20050905.xyz/admin` | `/srv/api/adminpage.py`（内联 SPA） | — 你自己运维用 |

**product 隔离**：同一个服务端同时服务 `aibox`（AI 工具箱）、`wfmc`（WFMC 启动器）、`dpc`（3D 打印成本计算器）。`product='wfmc'` 决定了：账号在哪个池子、公告发给谁、桌面登录回调段名 `wfmc://`。同一邮箱可以在不同 product 各注册一次，互不影响。

## 2. 客户端实际调用的接口（含代码位置）

所有业务请求带 `Authorization: Bearer <access_token>`；网页端用 Cookie（`sid` + `csrf`，域 `.20050905.xyz`）。

### 2.1 健康检查（不需要令牌）

| 接口 | 用途 | 客户端位置 |
|---|---|---|
| `GET /v1/health` | 启动时探测服务是否活着，10 秒超时 | `unifiedapi.ts: health()` |

返回里 `capacity.mem_total_mb` 是**判断「现在服务跑在哪台机器上」的唯一可靠指标**：`7944` = 笔记本（主），`373` = 棒子（备）。见第 6 节。

### 2.2 登录（浏览器 PKCE，客户端永远不碰密码）

四步，代码在 `src/main/cloudlogin.ts` + `unifiedapi.ts`：

1. 客户端生成 PKCE `verifier` + `challenge`，再生成随机 `state`
2. `shell.openExternal('https://api.20050905.xyz/v1/auth/desktop/start?challenge=…&state=…&product=wfmc')`
   → 系统浏览器打开登录页，用户输邮箱密码（可带 TOTP 二次验证 / 人机验证）
3. 客户端每 ~1.5 秒 `GET /v1/auth/desktop/poll?challenge=…`，最多等 5 分钟
   → 用户在浏览器里点「授权」后，poll 返回一次性 `code`
4. `POST /v1/auth/desktop/exchange {code, verifier}` → 返回 `access_token` + `user`

拿到令牌后用 `encryptToken()` 加密存本机。**退出登录只清本机令牌**，服务端会话到期自然失效。

校验令牌是否还有效：`GET /v1/me`（`cloudlogin.ts: refresh()`），返回 401 就自动登出。**客户端不调 `/v1/auth/refresh`**（服务端有，但令牌 30 天有效，用不上）。

### 2.3 云备份（WFMC「设置 → 云同步」里的备份）

| 接口 | 用途 |
|---|---|
| `GET /v1/backup` | 列表，返回 `items[]` + `limits{auto_keep, manual_keep}` |
| `POST /v1/backup/create` `{label}` | 把当前所有同步键打一份快照存到服务端，返回 `{id, keys, bytes}` |
| `GET /v1/backup/{id}/download` | 下载快照（JSON：`{backup, exported_at, items:{key:{value,version,updated_at}}}`） |
| `DELETE /v1/backup/{id}` | 删除（幂等） |
| `POST /v1/backup/{id}/restore` | 服务端侧回滚（**客户端当前没用**，回滚是客户端下载后自己写回） |

**保留份数由服务端定**，客户端只展示：`auto_keep`（自动备份保留几份）/ `manual_keep`（手动保留几份），值来自服务端 `store.backup_keep()`，后台可改。**别在客户端硬编码 3 / 5。**

### 2.4 云同步（键值对，带版本号）

| 接口 | 用途 |
|---|---|
| `GET /v1/sync` | 拉全部键 |
| `GET /v1/sync/{key}` | 拉单个，返回 `{key, value, version, updated_at}` |
| `PUT /v1/sync/{key}` `{value, base_version}` | 写单个，`base_version` 是客户端手里的版本号 |
| `POST /v1/sync/batch` | 批量写 |
| `DELETE /v1/sync/{key}` | 删 |
| `GET /v1/sync/revision` | 只要一个总版本号，用于判断「要不要拉」 |

**冲突语义**：`base_version` 和服务端当前版本不一致 → 返回 **409**。这是正常业务分支，不是故障，客户端应提示「云端有更新的版本」而不是重试覆盖。

**配额**（服务端常量，`/v1/me` 的 `quotas` 会回给客户端）：

| 项 | 默认值 | 环境变量 |
|---|---|---|
| 键数量上限 | 500 | `MAX_SYNC_KEYS` |
| 单键 value 大小 | 2 MB | `MAX_VALUE_BYTES` |
| 单账号总量 | 50 MB | `MAX_SYNC_BYTES` |

### 2.5 公告 / 通知（1.1.0 新增的通知中心）

| 接口 | 用途 |
|---|---|
| `GET /v1/notifications/public?product=wfmc` | **免登录**，只返回 `audience='public'` 的公告（未登录也要能收到更新通知） |
| `GET /v1/notifications` | 登录后拉自己账号的（含已读状态，`unread` 计数） |
| `POST /v1/notifications/read` `{ids}` | 标记已读 |

公告由运维在后台 `/admin` →「通知」页发；`display_mode` 决定客户端怎么弹：`silent` = 只在左侧「通知」页亮红点，`popup` = 启动后（和新通知到达时）弹**模态框 + Windows 右下角系统通知**（1.1.2 起实现，之前客户端只把 `mode` 读进来没用，所以选「弹窗」也只亮红点）。`level` 是 `info/warn/important`，界面上叫「公告 / 提醒 / 重要」。

客户端拉取节奏（不是推送，别指望秒级）：启动 ~6 秒拉第一次，之后每 60 秒一次；未登录只走 `/v1/notifications/public`（所以后台发「弹窗」通知时建议 `audience` 选「所有人」，否则未登录的人收不到）。

## 3. 错误约定（客户端靠它显示中文提示）

统一格式，HTTP 状态码 + JSON：

```json
{ "error": { "code": "rate_limited", "message": "注册太频繁，42 秒后再试" } }
```

`message` 是**中文人话，可以直接弹给用户看**，客户端不要自己再编一套文案。常见 `code`：

| code | 状态码 | 含义 |
|---|---|---|
| `validation_error` | 422 | 参数不对，可能带 `fields{}` 指出哪个字段 |
| `email_taken` | 409 | 该 product 下这个邮箱已注册 |
| `rate_limited` | 429 | 太频繁，带 `retry_after`（秒） |
| `unauthorized` / `session_expired` | 401 | 令牌无效或过期 → 客户端应登出 |
| `forbidden` | 403 | 权限不足（非管理员等） |
| `csrf_failed` | 403 | 来源不被允许（CORS/CSRF 校验失败） |
| `not_found` | 404 | 接口或资源不存在 |
| `internal_error` | 500 | 服务端异常，日志里一定有 traceback |

## 4. 数据存在哪

PostgreSQL 单库 `appdb`（笔记本 WSL 里，容器 `pg-main`），核心表：

| 表 | 内容 |
|---|---|
| `account` | 账号（**按 product 隔离**，邮件明文 + 密码 `scrypt` 哈希 + 明文密码加密留档，供用户自助查看） |
| `session` | 登录会话（只存令牌的 sha256，30 天 TTL） |
| `sync_item` / `sync_item_history` | WFMC 云同步的键值 + 历史版本 |
| `backup_snapshot` | 备份快照的元数据（**包体不在库里**，在磁盘上） |
| `app_notification` / `notification_read` | 公告与已读 |
| `mfa_totp` | 二次验证（TOTP 密钥加密存） |
| `audit_log` | 审计流水（登录、改密、切库、后台操作全都记） |
| `login_attempt` / `email_code` | 限流与验证码 |

备份包本体：`/srv/db/backups/`（服务端整库 dump，如 `appdb-20261107-170542.sql.gz`），WFMC 用户快照存在同一套备份目录体系里。

## 5. 运维事实（客户端不感知，但你排障必须知道）

### 5.1 双机热备

| | 笔记本（当前主） | 棒子（备） |
|---|---|---|
| 形态 | Windows 11 + WSL2 Ubuntu | 4G 小主机（ARM，373MB 内存 / 6.7G 磁盘） |
| 隧道 | `883b52ac-…` | `eb8876b6-…` |
| 健康指标 | `mem_total_mb: 7944` | `mem_total_mb: 373` |

- 谁在主位，**只看 `api.20050905.xyz` 的 CNAME 指向哪条隧道**。切换命令：`scripts/switch-api.ps1 -Target laptop|stick`（后台等价物 `POST /v1/admin/site/switch`）。
- `failover.timer` 每 3 分钟探一次：公网连续 3 次不可用 + 对端失联 + 本机健康 → 把 `api` 抢到自己身上。**只切走、不切回**，笔记本睡醒后要手动切回来。
- 切过去之后：棒子只有 373MB 内存，只适合短时顶班。
- 2026-11-07 实测：切到棒子 17 秒生效，切回 6 秒生效，两边数据指纹完全一致。

### 5.2 Cloudflare 前面有两件事

1. **`/admin` 和 `/v1/admin/*` 挂着 Cloudflare Access**（防攻击刻意加的）。**`/v1/*` 业务接口绝不能挂 Access**，否则客户端带的 Bearer 令牌会被边缘全拦 → 全部 401/302。
2. **Cloudflare 对 `python-urllib` 默认 UA 直接 403**。自己写探针/健康检查脚本必须带自定 UA（服务端代码里 `adminops.py` 伪装成 Chrome、`siteswitch.py` 带 `ltserver-siteswitch/1.0`）。判断「服务挂了」之前先换 `curl` 复核一次 —— 2026-11-07 就被这个坑误导过一次，以为切换失败，其实服务好好的。

### 5.3 自动更新不走服务端

WFMC 的自动更新读 **GitHub Release**（`steveliuyan/wfmc`，产物 `WFMC-Setup-x.y.z.exe` / `WFMC-Portable-x.y.z.exe`）。**服务端挂了不影响客户端更新**，两者完全解耦。

## 7. 改东西的正确顺序（别乱）

- **只改客户端、不动协议**：随便发版，服务端不用动。
- **要改接口**：先改文档（本文件 + 服务端 `H:\笔记本服务器\docs\交接文档.md`）→ 服务端上线（先加字段、后改行为，保证老客户端不炸）→ 客户端再跟进。**确实要破坏兼容就升 `/api/v2`**。
- 服务端怎么发布（改 `H:\笔记本服务器\docker\apps\api\*.py` → 传到笔记本 → WSL 里覆盖 `/srv/api/` → `python3 -m py_compile` → `systemctl restart ltserver-api`）见 `H:\笔记本服务器\docs\交接文档.md` 第 7 节。**双机都要发**：笔记本和棒子各自一份 `/srv/api`，改完记得同步（2026-11-07 已做过一次全量对齐，8 个文件 sha256 全等）。

## 8. 常见疑问 FAQ

**Q：用户说「云备份失败」，先看哪？**
A：① `curl /v1/health` 看 `db` 是不是 `true`；② `mem_total_mb` 是不是 7944（打到棒子上了？）；③ 后台 `/admin` → 通知/审计里看有没有 500；④ `journalctl -u ltserver-api -n 100`。

**Q：公告发了客户端不弹？**
A：① 后台那条要选「弹窗（打开应用就弹出来）」，选「静默」只会亮红点；② 未登录状态只能看到 `audience='public'`（后台叫「所有人」）的，声明给账号的通知必须登录；③ 客户端是**拉取式**：启动 6 秒后拉第一次、之后每分钟一次，不是推送；④ 便携版（Portable）没有开始菜单快捷方式，Windows 可能吞掉右下角系统通知 —— 但应用内模态框一定会弹，看到模态框就说明链路是通的。

**Q：为什么登录要开浏览器？**
A：密码只交给网页（服务端统一账号），客户端只拿一次性 `code` 换令牌（PKCE），客户端代码里没有任何密码逻辑 —— 这是刻意设计，别改成「客户端直连密码登录」。

**Q：棒子能长期当主吗？**
A：不建议。373MB 内存 + 4.4G 磁盘，只适合笔记本休眠时短时顶班。长期主位是笔记本。

**Q：服务端会崩吗？**
A：单个 Python 进程，systemd `Restart=always`，崩了 3 秒自动拉起；数据库有 `pg-backup` + 每天推送备份到对端。真正要担心的是笔记本睡眠/断网（2026-11-07 发生过一次，公网被棒子接管）。
