# WFMC 开发规范手册

> 这份手册管「怎么写」，不管「写了什么」。功能为什么这么设计、踩过哪些坑，看 `HANDOFF.md`（尤其 §13 踩坑清单、§14 版本演进）；发版照着 `AGENTS.md` + `HANDOFF.md` §1.5 做。
> 有冲突时：**代码现状 > 这份手册 > 记忆**。发现手册过时，当场改手册，别只在心里记。

---

## 1. 代码规范

### 1.1 硬门槛（每次改完都要绿）

```powershell
npm run typecheck      # tsc --noEmit，0 error
npm run test:core      # 纯函数断言，全过
npm run i18n:check     # 渲染层中文覆盖 100%
npm run build          # build:main + build:renderer
```

四条里任何一条红了都不算改完。**不要靠「看起来能跑」交差。**

### 1.2 目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `src/main/` | 业务逻辑、文件系统、网络、Electron 生命周期 | JSX、DOM 操作、`window` |
| `src/renderer/` | React 组件、样式、i18n 表 | `fs`/`path`/直接 `net`/直接 `fetch` 内部接口 |
| `src/shared/` | 跨进程共享的**类型**与纯工具函数 | 有副作用的代码、import electron |
| `scripts/` | 构建 / 发版 / 一次性探针脚本 | 会被运行时代码 import 的模块 |
| `build/` | electron-builder 配置、`installer.nsh`、图标位图 | 业务代码 |
| `docs/` | 设计稿、交接、本手册 | 会被打包的资产 |

- 主进程不放 UI 逻辑；渲染层不碰系统能力 —— 一律走 IPC。这是为了以后能换成「本地 UI + 云端服务」而不动前端。
- 新模块命名跟现有文件一致：单词小写（`launch.ts`、`tray.ts`），多词用连字符（`mcp-stdio.ts`、`build-main.mjs`）；React 组件用 `PascalCase.tsx`（`McpPanel.tsx`）。

### 1.3 编码与文本

- **一律 UTF-8 无 BOM**。`package.json` 写成带 BOM 会让 vite 当 PostCSS 配置解析、直接构建失败（`Unexpected token '\uFEFF'`）。
- **不要用 PowerShell 的 `Get-Content` / `Set-Content` 批量改含中文的源码**：PS 5.1 默认按 ANSI 解码，改完中文全乱码（这是真出过的事，见 HANDOFF §13.4）。
  - 要改：用编辑器；要脚本改：`[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`，或 `node -e` / 临时 `.cjs`。
  - `node -e "…"` 里的引号会被 PowerShell 吃掉 —— 写临时 `.cjs` 脚本，`@'…'@` here-string 防插值，跑完删掉。
- 中文注释写**为什么**，不写「是什么」。看到一段代码要先想「为什么它必须这样」，那句才值得写下来。

### 1.4 TypeScript

- `strict` 全开。不给 `any` 开后门；外部数据（用户文件、网络响应、MCP 入参）进来第一件事就是校验/窄化。
- 共享类型只在 `src/shared/types.ts` 定义一次。**两边各写一份形状会在改字段那天炸**。
- 枚举式联合（`LoaderType`、`ResourceType`）扩展后，`Record<T, X>` 的地方 tsc 会点名，照着补，别用 `as any` 糊过去。
- 纯函数（能断言的）抽到不依赖 electron / fs 的文件里，供 `test:core` 覆盖。

### 1.5 出错与日志

- 会抛的错就抛，别吞；`ipcMain.handle` 抛出的 message 会到渲染层。
- 需要留痕的失败调 `logError(scope, message, detail?)`（`src/main/errlog.ts`），scope 用 `模块:动作`（如 `mcp:launch_instance`）。
- 给用户看的错误必须过 `friendlyError()`（`api.ts`），别把 `fetch failed` 甩到界面上。
- 耗时操作一律 `runTask(kind, title, fn, opts)`：可取消、任务面板可见、失败要发终态，**否则进度条永远停在那一格转圈**（1.3.2 修过）。

## 2. IPC 与事件通道规范

### 2.1 命名

- 通道名固定 `<域>:<动作>`，全小写、动作用连字符：`instance:list`、`content:diagnose`、`mcp:consent-reply`。域名与模块名对齐（`modrinth.ts` → `modrinth:*`）。
- 事件通道统一 `event:<域>-<动作>`：`event:launch-log`、`event:task`、`event:mcp-consent`。

### 2.2 三处必须同步改

加一个能力要动三/四个地方，缺一个就编译不过或运行时报「没有这个方法」：

1. **主进程**：业务函数写在模块里，`src/main/ipc.ts` 只做转接（参数校验、调用、返回）。
2. **`src/preload/index.ts`**：`bridge.invoke` 暴露白名单；**新增事件必须在 `EventChannel` 联合类型里加一项**，否则渲染层 `bridge.on('event:xxx')` 类型不过。
3. **`src/renderer/api.ts`**：包成 `call<T>(…)` 方法，挂在 `api` 对象上；事件包成 `onXxx(cb)`。
4. 类型：请求/响应的形状放 `src/shared/types.ts` 或 `api.ts` 就近声明（渲染层专用的就近）。

### 2.3 载荷与返回

- 载荷必须是**可结构化克隆的纯对象**：不放函数、类实例、`Map`、`Buffer`（要传二进制给 `Uint8Array` 或临时文件路径）。
- 返回值二选一：成功返数据，失败抛错。不要发明 `{ok:false}` 这种主进程 → 渲染层的返回协议（HTTP 桥那层例外，见 §2.5）。
- 大对象先瘦身再跨进程：图片/`base64`/`icon` 一律剔掉，长字符串截断（参考 `mcp.ts` 的 `slim()`）。
- 长任务不要用 `invoke` 等（会把渲染层卡住）：走 `runTask`，进度用 `event:task` / `event:progress` 推。

### 2.4 安全

- 渲染层不直接读文件、不发网络请求；主进程也不接受来自渲染层的任意路径做危险操作（要校验在允许的 dataDir 内）。
- 对外部世界（MCP、HTTP、命令行参数）暴露的每一个入口都要**默认拒绝**：令牌校验、写操作要人确认、超时当拒绝。

### 2.5 MCP 那层是例外，规则单独记

HTTP 桥因为要给本机别的进程用，返回协议是 `{ok:true,result}` / `{ok:false,error:{message}}`，且**一律 HTTP 200**（错误码交给 body，AI 客户端才不会把 4xx 当网络故障）。细节见 HANDOFF §14.19。

## 3. i18n 规范

### 3.1 目标

渲染层**所有**面向用户的中文都要进 i18n 表，`npm run i18n:check` 卡 **100%**（脚本 `--min 100`，低一条就 exit 1）。当前规模：约 1372 条中文字面量。

### 3.2 表在哪

- `src/renderer/i18n-parts/*.ts`：按页面分文件（`app` / `hosting` / `instances` / `manage` / `misc` / `online` / `resources` / `settings`），每条是「中文原文 → 各语言」。
- `src/renderer/i18n-dynamic.ts`：带变量的动态文案用正则规则匹配，不在 parts 里逐条列。

### 3.3 新增文案的流程

1. 正常写中文 JSX / 字符串。
2. `npm run i18n -- --list` 看哪几条没翻。
3. 在对应 `i18n-parts/xxx.ts` 加精确对；带变量的写成动态规则。
4. 再跑 `npm run i18n:check`，必需 100%。

### 3.4 红线

- **不许为了过卡口把中文改成拼音、英文或空字符串**。
- 不许在 parts 里堆一条匹配一切的通配规则（会掩盖真实漏翻）。
- JSX 里被 `<strong>` / 表达式切开的片段按**单个文本节点**分别入表。
- 主进程日志、内部错误文案不进 i18n（给开发者看）；用户可见的对话框、toast、按钮全部要过表。
- 五种语言都要给；某语言确实没有对应说法就用最贴近的意译，别留空。

## 4. 构建与发版规范

### 4.1 构建链路

- 主进程：`npm run build:main` = `scripts/build-main.mjs`（esbuild）。**三个入口**：
  - `src/main/index.ts` → `dist/main/index.js`
  - `src/preload/index.ts` → `dist/main/preload.js`
  - `src/main/mcp-stdio.ts` → `dist/main/mcp-stdio.js`（要 `ELECTRON_RUN_AS_NODE=1` 直接跑，所以必须独立 bundle + `asarUnpack`）
- 渲染层：`npm run build:renderer` = vite。
- 开发：`npm run dev`（`scripts/dev.mjs`，vite dev server + electron）。
- 第三方包一律 `packages: 'external'`：`@xmcl/*` 里有动态 `require`，打进 bundle 会碎。

### 4.2 新增一个「能被独立进程执行」的入口时

三件套缺一不可：esbuild 加 entry → `package.json` 的 `build.asarUnpack` 加上那个产物 → 运行时用「先 `resourcesPath/app.asar.unpacked/…`、退回 `app.getAppPath()/…`」的方式定位（参考 `mcpStdioScript()`）。

### 4.3 版本与打包

- 版本号**只改** `package.json` 的 `"version"`，保持无 BOM。
- `npm run dist` → `release\WFMC-Portable-X.Y.Z.exe` + `WFMC-Setup-X.Y.Z.exe`。
- 打完 `release\` 里**只留当前版本两个 exe**，顺手删 `builder-debug.yml`。
- 发版全流程以 `HANDOFF.md` §1.5 为准：打 → 发 Release（两个附件，上传 10 分钟起，放后台）→ **删旧 release**（只留最新一个，否则更新源会串版本）→ 推源码（走 Git Data API，本项目没有 git）→ 复核。

### 4.4 提交前自检清单

- [ ] `typecheck` / `test:core` / `i18n:check` / `build` 全绿
- [ ] 真机起一遍，改的那条路径亲手点过（截图或日志留证）
- [ ] `scripts/` 里自己造的 `tmp-*`、探针脚本、`.tmp-ud` 测试目录删干净
- [ ] 改过主进程入口 / `package.json` 的 `build` 段：重打包验一次
- [ ] `HANDOFF.md` 补小节（为什么这么改、怎么验证、坑在哪）

## 5. 测试规范

### 5.1 纯函数断言（`npm run test:core`）

- 位置：`scripts/test-core.mjs`（跑）+ `scripts/tests/core.ts`（断言）。当前 17 组。
- 准则：**只测纯函数** —— 不碰 electron、不碰真实文件系统、不发网络。典型对象：路径推导、版本号命名、json 合成、maven 坐标 → 路径、护栏函数（不瞎补、不瞎删）。
- 一个断言组写清「它防的是什么回归」，比如「空 url 补地址的护栏（前缀对不上不瞎补）」。
- 靠 IO 与流程吃饭的功能（MCP、安装、启动）不进 `test:core`，靠真机验证清单。

### 5.2 真机验证清单

1. 用隔离 userData 起：`electron.exe . --user-data-dir=H:\…\scripts\.tmp-ud`，别污染自己的数据。
2. **`settings.json` 必须在 `<userData>\settings.json`**（userData 根），不是 `<userData>\data\settings.json` —— 后者是实例数据目录，放了不生效，会得到「设置没生效」的假象。
3. 改设置 → 重启后确认真的读到（端点文件、开关行为）。
4. 写操作要验「拒绝」和「允许」两条路，不能只验成功的。
5. 留证：截图 / 日志 / 接口返回原文，写进 HANDOFF 的验证记录。

### 5.3 一次性探针脚本

临时脚本一律放 `scripts/`、名字带 `tmp-`，跑完删。想留下当回归用的，改名进 `scripts/tests/` 并在 `test-core.mjs` 里挂上。
